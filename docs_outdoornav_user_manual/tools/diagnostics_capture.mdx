The `nav_diagnostics_capture.py` script collects an OutdoorNav diagnostics snapshot for troubleshooting
and support. It monitors the ROS graph, topic rates, diagnostics, logs, transforms, navigation goals,
localization, and the velocity command chain. It also queries lifecycle states and node parameters,
and retrieves service and Docker logs.

**Running the capture on the robot PC is recommended.** Remote capture is also supported, but depends
on network visibility, installed ROS interfaces, and separate access to the robot's logs.

## Capture on the Robot PC

SSH into the robot PC. An SSH terminal running the script on the robot
is considered a **local capture**; it does not require the remote-log flags that will be mentioned later.

1. Keep OutdoorNav running and source the robot's ROS 2 Jazzy and workspace environment in this terminal.
   The environment must use the robot's middleware and domain ID and provide its ROS message packages.
   The script also requires Python's `yaml` (PyYAML) and `matplotlib` packages. Recording a bag requires `ros2 bag`.
2. Change to the installed application directory, replacing `<version>` with the running OutdoorNav version:

   ```bash
   onav cd <version>
   ```

3. Cache sudo credentials for reading the service journal, then run the capture as your normal user:

   ```bash
   sudo -v
   python3 scripts/nav_diagnostics_capture.py
   ```

   The user must also have permission to list Docker containers. Dozzle must be available at
   `http://127.0.0.1:5200/_/logs`, or at the URL supplied with `--dozzle-url`.

4. Capture while the issue is occurring, following the robot's normal safety procedures. The default
   monitoring window is 60 seconds. Press `Ctrl+C` **during monitoring** to finish the window early
   and write the results, or use the `--duration` flag to set a specific monitoring window.

5. Open `summary.md` in the capture directory and attach the generated `.tar.gz` archive to the support request.

For a longer capture with a bag and a specific robot namespace:

```bash
python3 scripts/nav_diagnostics_capture.py --duration 120 --bag
```

Choose a writable destination with `--output` if the current directory is not writable.

:::note

The duration is the monitoring window, not the total runtime. Discovery, service queries, log downloads,
plot generation, and archiving add time. Docker logs include all history still retained by Docker,
not just the monitoring window; the service journal covers the latest start of
`clearpath-platform-extras.service`.

:::

## Capture from a Remote PC

First, follow the [OutdoorNav middleware connection guide](https://github.com/cpr-application/clearpath_outdoornav/blob/ros2/middleware/README.md)
to connect the remote PC to the robot using Zenoh or Cyclone DDS.

The robot and remote PC must use the same middleware and ROS domain ID. Keep the script and its YAML
configuration together on the remote PC, and source any workspace containing the robot's custom message
and action interfaces. The Python dependencies listed for local capture must also be installed on the remote PC.

For example, after completing the middleware setup, run the following on the remote PC. Replace the
example address with the robot's reachable address and use its domain ID:

```bash
export ROS_DOMAIN_ID=0 # Replace with the robot's ROS domain ID if different
cd ~/onav_ws/src/onav-app
source api/middleware/connect_robot.sh zenoh 192.168.131.1
python3 scripts/nav_diagnostics_capture.py \
  --remote-service-logs --remote-docker-logs --ssh-host 192.168.131.1
```

For Cyclone DDS, use the connection guide's `cyclone_dds` command instead. Run the capture in the same
shell as the connection command. Results are written on the **remote PC**, not the robot.

### Remote Access Requirements and Limitations

- **ROS access and SSH access are separate.** The middleware connection carries ROS data. The
  `--remote-service-logs` flag retrieves the robot's journal over SSH, and `--remote-docker-logs` lists
  the robot's containers over SSH before downloading their logs through Dozzle.
- **SSH is non-interactive.** The script requires a previously verified, trusted host key and key or
  agent authentication. It cannot prompt for a login password, key passphrase, or host-key confirmation.
  Establish and verify SSH access separately before capturing; do not disable host-key checking.
- **The remote journal requires passwordless sudo.** The SSH user must be authorized to read the
  journal through non-interactive sudo. Running `sudo -v` on your remote PC does not grant sudo access
  on the robot. Ask your administrator to provision the required access, or capture locally instead.
- **Remote Docker access requires Docker permissions.** The SSH user must be able to list containers
  without an interactive sudo prompt.
- **Dozzle must be reachable separately.** With `--remote-docker-logs`, the default URL is
  `http://<ssh-host>:5200/_/logs`. A Zenoh SSH tunnel does not automatically forward Dozzle.
  If needed, arrange a separate port forward and set `--dozzle-url` to its local URL.
  Setting only `--dozzle-url` does not make container listing remote; retain `--remote-docker-logs`.
- **SSH ports and jump hosts are not script arguments.** Configure an SSH host alias in `~/.ssh/config`
  for these settings and pass that alias with `--ssh-host`. If the alias is not directly reachable
  over HTTP, also provide the separately reachable Dozzle URL.
- **The default log sources are local.** When running on a remote PC, omitting the remote flags tries
  to collect that PC's journal and Docker logs, not the robot's.
- **Remote measurements reflect the network.** Topic rates and TF age can be affected by latency,
  packet loss, clock synchronization, and bandwidth. Missing message/action packages prevent some
  subscriptions or action-result retrieval. Avoid `--include-heavy` over bandwidth-limited links.
  Environment information describes the PC executing the script.

When SSH or Dozzle access is unavailable, capture the ROS data without either log source:

```bash
python3 scripts/nav_diagnostics_capture.py --skip-service-logs --skip-docker-logs
```

This is a partial capture. Collect the missing logs locally on the robot if they are needed.
Log retrieval failures are reported as warnings and recorded in the results; they do not by themselves
prevent the ROS capture from being saved.

## Command-Line Arguments

Run `python3 scripts/nav_diagnostics_capture.py --help` to view usage. The following defaults apply
when the arguments are omitted.

| Argument                        | Default                                                                                                                          | Description                                                                                                                                                                                                |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `-h`, `--help`                  | Not requested                                                                                                                    | Show usage and exit. The ROS Python environment and YAML file must still be available because they are loaded before argument parsing.                                                                     |
| `--namespace NAME`              | `ROBOT_NAMESPACE`, otherwise auto-detected                                                                                       | Robot namespace. Automatic detection selects the most common first namespace component among visible topics, excluding `namespace_exclude` entries.                                                        |
| `--duration SECONDS`            | `60.0`                                                                                                                           | Topic, diagnostic, and log monitoring window.                                                                                                                                                              |
| `--bag`                         | `false`                                                                                                                          | Also record rate-monitored topics, ROS log topics, and TF topics with `ros2 bag`. This is not a recording of every visible topic.                                                                          |
| `--discovery-timeout SECONDS`   | `20.0`                                                                                                                           | Maximum initial wait for the ROS graph.                                                                                                                                                                    |
| `--service-timeout SECONDS`     | `5.0`                                                                                                                            | Timeout per lifecycle or parameter service call.                                                                                                                                                           |
| `--output DIRECTORY`            | `nav_diag_<namespace>_<YYYYMMDD_HHMMSS>` in the current directory                                                                | Capture directory. The archive is created beside it unless disabled.                                                                                                                                       |
| `--topics [TOPIC ...]`          | Empty list                                                                                                                       | Additional visible topics to rate-monitor. Relative names use the selected robot namespace; absolute names are unchanged. Explicitly listed topics can include heavy types even without `--include-heavy`. |
| `--include-heavy`               | `false`                                                                                                                          | Include point clouds and images in general rate monitoring. Increases bandwidth and, with `--bag`, recording size.                                                                                         |
| `--skip-params`                 | `false`                                                                                                                          | Skip node parameter dumps. By default, parameters are queried for nodes under the robot namespace that expose parameter services.                                                                          |
| `--ssh-host HOST`               | `ROBOT_IP`, then `ROBOT_HOST`, otherwise unset                                                                                   | Robot SSH address or configured SSH alias for remote journal and container listing. Also supplies the host in the default remote Dozzle URL.                                                               |
| `--ssh-user USER`               | `robot`                                                                                                                          | User for remote SSH connections.                                                                                                                                                                           |
| `--remote-docker-logs`          | `false`; local collection                                                                                                        | List robot containers through SSH and download their retained logs through Dozzle.                                                                                                                         |
| `--skip-docker-logs`            | `false`                                                                                                                          | Skip Docker log collection. Mutually exclusive with `--remote-docker-logs`.                                                                                                                                |
| `--dozzle-url URL`              | `DOZZLE_URL` if set; otherwise `http://127.0.0.1:5200/_/logs` locally or `http://<ssh-host>:5200/_/logs` with remote Docker logs | Dozzle base URL used for the log archive download.                                                                                                                                                         |
| `--dozzle-host LABEL`           | `DOZZLE_HOSTNAME`, otherwise `localhost`                                                                                         | Dozzle host label used to identify containers. This is not an SSH hostname or a replacement for `--dozzle-url`.                                                                                            |
| `--docker-logs-timeout SECONDS` | `600.0`                                                                                                                          | Timeout supplied to the Dozzle archive download request.                                                                                                                                                   |
| `--remote-service-logs`         | `false`; local journal                                                                                                           | Retrieve the robot's latest `clearpath-platform-extras.service` invocation journal over SSH.                                                                                                               |
| `--skip-service-logs`           | `false`                                                                                                                          | Skip this service journal. Mutually exclusive with `--remote-service-logs`.                                                                                                                                |
| `--no-archive`                  | `false`                                                                                                                          | Leave the capture directory without creating the `.tar.gz` archive.                                                                                                                                        |

## Capture Results

The capture directory contains:

| Location       | Contents                                                                                                                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `summary.md`   | Findings and links to supporting evidence. Start here.                                                                                                                                             |
| `navigation/`  | Trajectory, goal, localization, and velocity-chain results, including plots. Plots are generated even when data is missing, with annotations explaining the missing data.                          |
| `ros/`         | Graph snapshot, topic list and rates, lifecycle states, and diagnostic messages.                                                                                                                   |
| `tf/`          | Transform edges, lookup results, and frame information.                                                                                                                                            |
| `logs/`        | ROS logs, service journal, Docker log ZIP, and collection status/error files.                                                                                                                      |
| `environment/` | Execution environment, optional ping results, available middleware config files, and the exact diagnostics YAML used. Ping is attempted only when `ROBOT_IP` and the `ping` command are available. |
| `parameters/`  | Node parameter dumps and any parameter query errors; omitted with `--skip-params`.                                                                                                                 |
| `bag/`         | Optional bag recording.                                                                                                                                                                            |

After writing results, the script exits with status `1` if the summary contains an `ERROR` finding,
or `0` otherwise. An error finding therefore does not necessarily mean that capture failed.
ROS discovery failure exits before producing a normal capture.

Captures may contain network addresses, environment settings, node parameters, and logs from **all**
containers on the selected Docker host. Review them before sharing, and use an approved support channel.

## Diagnostics Parameter File

The script loads `nav_diagnostics_config.yaml` from the **same directory as the script**, regardless
of the current working directory. For an installed deployment this is
`/opt/onav/<version>/app/scripts/nav_diagnostics_config.yaml`; in a source checkout it is
`~/onav_ws/src/onav-app/scripts/nav_diagnostics_config.yaml`.

There is no `--config` argument. Edit that file before starting the script to adjust capture conventions
and report thresholds. These are diagnostics-analysis settings, **not** ROS node parameters: changing
them does not tune navigation or alter robot safety limits. Keep the required keys and YAML types.
A missing, invalid, or incomplete configuration prevents startup.

### Graph, Topics, and Diagnostics

The lists and mappings below use the defaults shown above. Topic names in the key-topic and velocity
configuration are relative to the selected robot namespace.

| Parameter               | Description                                                                                                                                                                  |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `heavy_types`           | Message types excluded from general rate monitoring unless `--include-heavy` is enabled or the topic is explicitly added with `--topics`.                                    |
| `nav_nodes`             | Navigation node names expected under the robot namespace. Missing nodes produce errors.                                                                                      |
| `localization_nodes`    | Localization node names expected under the robot namespace. Missing nodes produce errors.                                                                                    |
| `scan_candidates`       | Ordered candidate filtered-scan topics. The first visible candidate is checked; no candidate produces an error.                                                              |
| `key_topics`            | Key topic names mapped to whether silence is expected while idle: `true` permits no messages; `false` requires received data. Missing topics or publishers are still errors. |
| `localization_topics`   | Additional key topics using the same Boolean convention, merged into `key_topics` for summary checks.                                                                        |
| `tf_lookups`            | Transform lookup pairs in `[target_frame, source_frame]` order. Failed lookups produce errors.                                                                               |
| `log_levels`            | Numeric ROS log levels mapped to their report labels.                                                                                                                        |
| `diagnostic_levels`     | Numeric diagnostic status levels mapped to report labels.                                                                                                                    |
| `diagnostic_severity`   | Ranking used to retain the worst diagnostic status. Larger ranks are more severe; the default places `ERROR` above `STALE`, then `WARN`, then `OK`.                          |
| `environment_variables` | Environment variable names saved in `environment.json`; values come from the PC running the capture.                                                                         |
| `namespace_exclude`     | First namespace components ignored during automatic robot namespace selection.                                                                                               |

### Localization and Timing Thresholds

| Parameter                        | Default        | Description                                                                                                 |
| -------------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------- |
| `clock_skew_limit_s`             | `0.5` s        | Warn when median TF age is outside plus or minus this limit. This can indicate clock skew or network delay. |
| `localization_std_xy_limit_m`    | `0.25` m       | Position standard-deviation warning threshold.                                                              |
| `localization_std_yaw_limit_deg` | `10.0` degrees | Yaw standard-deviation warning threshold.                                                                   |
| `map_odom_jump_limit_m`          | `0.25` m       | Translation change between successive map-to-odom samples above which a jump is reported.                   |
| `map_odom_jump_limit_deg`        | `10.0` degrees | Rotation change between successive map-to-odom samples above which a jump is reported.                      |

### Goals and Actions

| Parameter                         | Default                                                     | Description                                                                                                                                                        |
| --------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `goal_status`                     | Mapping shown above                                         | Numeric ROS action statuses mapped to names.                                                                                                                       |
| `terminal_goal_status`            | `SUCCEEDED`, `CANCELED`, `ABORTED`                          | Status names treated as completed goals.                                                                                                                           |
| `navigation_actions`              | `navigate_to_pose`, `navigate_through_poses`                | Action names classified as navigation goals in analysis.                                                                                                           |
| `feedback_actions`                | `navigate_to_pose`, `navigate_through_poses`, `follow_path` | Action names whose feedback is also monitored.                                                                                                                     |
| `result_request_timeout_s`        | `5.0` s                                                     | Maximum wait for a queued goal's result service to become available.                                                                                               |
| `goal_pose_match_before_s`        | `2.0` s                                                     | Time before a goal is first observed in which a matching goal pose may be found.                                                                                   |
| `goal_pose_match_after_s`         | `0.5` s                                                     | Time after a goal is first observed in which a matching goal pose may be found.                                                                                    |
| `capture_startup_status_window_s` | `2.0` s                                                     | Startup window used to identify goals already present when the first action-status message arrives. Terminal goals are also classified as starting before capture. |

### Velocity Command Analysis

Linear velocity components are measured in m/s and angular velocity in rad/s. The numeric velocity
thresholds below are applied to each component; a sample is moving if any component's magnitude exceeds
the relevant threshold.

| Parameter                    | Default                                     | Description                                                                                                                                                                              |
| ---------------------------- | ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `velocity_chain`             | Ordered topic/description pairs shown above | Command stages compared in order, from navigation output to platform input.                                                                                                              |
| `velocity_stage_checks`      | Mapping shown above                         | Troubleshooting hints keyed by downstream stage topic, used when command propagation is low. Keep these aligned with `velocity_chain`.                                                   |
| `teleop_inputs`              | Topic/label mapping shown above             | Teleoperation velocity topics checked for activity overlapping navigation commands.                                                                                                      |
| `stop_locks`                 | Topic/label mapping shown above             | Boolean stop topics checked for engaged periods.                                                                                                                                         |
| `measured_velocity_topic`    | `platform/odom`                             | Topic providing measured velocity for command tracking.                                                                                                                                  |
| `collision_state_topic`      | `navigation/collision_monitor/state`        | Collision monitor state topic used to report interventions.                                                                                                                              |
| `velocity_extractors`        | Message-type/field-path mapping shown above | How to extract a Twist from each supported message type. `self` means the message itself; dotted paths traverse nested fields.                                                           |
| `collision_actions`          | Mapping shown above                         | Numeric collision monitor actions mapped to names.                                                                                                                                       |
| `twist_mux_timeout_s`        | `0.5` s                                     | Matching window for downstream commands and teleoperation overlap, and maximum command age for measured-velocity comparison. This does not change the robot's twist multiplexer timeout. |
| `zero_velocity`              | `0.001`                                     | Threshold for counting non-zero velocity samples.                                                                                                                                        |
| `moving_velocity`            | `0.05`                                      | Threshold selecting moving commands for propagation and tracking analysis.                                                                                                               |
| `stalled_velocity`           | `0.01`                                      | Measured-velocity threshold below which a moving-command sample is considered stationary.                                                                                                |
| `min_command_samples`        | `5`                                         | Minimum moving-command sample count for propagation calculations and stall warnings.                                                                                                     |
| `pass_through_limit_percent` | `50.0`%                                     | Warn if the proportion of moving commands matched at the next stage falls below this percentage.                                                                                         |
| `velocity_match_tolerance_s` | `0.05` s                                    | Allow a downstream sample this much earlier than an upstream command when matching propagation. The later bound uses `twist_mux_timeout_s`.                                              |
| `stalled_command_percent`    | `50.0`%                                     | Warn when at least this percentage of matched moving-command samples show no measured motion, provided the minimum sample count is met.                                                  |
